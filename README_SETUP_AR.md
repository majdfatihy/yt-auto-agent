# إعداد الإصدار الثالث

ارفع agent.py وtelegram_poll.py وrequirements.txt إلى جذر المستودع، وارفع ملفي .github/workflows/main.yml و.github/workflows/telegram-poll.yml إلى مساريهما الموضحين. احذف ملف workflow القديم إن كان يكرر نفس التشغيل.

## Secrets المطلوبة
TELEGRAM_TOKEN وTELEGRAM_CHAT_ID وGEMINI_API_KEY وYT_CLIENT_ID وYT_CLIENT_SECRET وYT_REFRESH_TOKEN. الكوكيز YT_COOKIES اختيارية، ولا تضمن تجاوز تحقق يوتيوب.

## الاختبار
1. شغّل Telegram Inbox يدويًا من Actions، أو انتظر موعد الجدولة (كل خمس دقائق تقريبًا، وقد تتأخر GitHub Actions).
2. أرسل رابط فيديو من قناتك إلى البوت. سيُرسل repository_dispatch إلى workflow الرئيسي.
3. إذا رفض يوتيوب التنزيل، أرسل MP4 مع رابط الفيديو نفسه في caption. سيُشغّل طلبًا جديدًا باستخدام ملف تيليجرام.
4. الحد الرسمي لتنزيل ملفات بوت تيليجرام عبر Bot API السحابي هو 20MB. الملفات الأكبر تتطلب خادم Telegram Bot API محلي أو مسار نقل آخر (غير منفذ في هذه النسخة).
5. النشر إلى يوتيوب Private أثناء الاختبار؛ لا يتم تفعيل فيسبوك إلا عند وجود مفاتيحه في المستودع.

## حدود واحتياطات
- لا تستخدم بوت تيليجرام مع webhook أو polling آخر بالتزامن؛ getUpdates قد يتعارض معه.
- يجب أن تكون GitHub Actions مفعّلة، وworkflow Telegram Inbox موجودًا في الفرع الافتراضي لكي تعمل الجدولة.
- استخراج نصوص الفيديو من عنوان NoEmbed وحده غير موثوق. عند إرسال MP4، يحاول Gemini فهم الفيديو أولًا، وقد يفشل بسبب الحصة أو قيود حجم الملف. إذا لم يتوفر تفريغ موثوق، لا يمكن ضمان دقة المقطع.
- لم يتم اختبار الوصول إلى حساب تيليجرام أو قناتك أو مفتاح Gemini في هذه البيئة.
