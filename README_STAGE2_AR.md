# تحديث وكيل يوتيوب — المرحلة الثانية: اختيار القص بالأرقام

## نتيجة اختبار المرحلة الأولى (GitHub Actions — 4 نوفمبر 2026)

- `SOURCE: TELEGRAM_MP4; FILE_RECEIVED: YES; FILE_VALIDATED: YES`
- `TRANSCRIPTION: GROQ; CUES: 16`
- `CLIP_PLANNER: GEMINI_MODEL: gemini-3-flash-preview; CANDIDATES: 3`
- `CLIP_PLAN: SAVED; CLIPS: 3; STORAGE: TELEGRAM_CLIP_PROPOSALS`
- لم يحدث أي قص أو نشر أثناء `/prepare`.

## الملفات التي تغيرت في المرحلة الثانية

- `agent.py`: مسار `preview` منفصل عن `/prepare` و`/seo`. يقص المقاطع التي اختارها المستخدم فقط، ويبعث كل فيديو كمعاينة إلى تيليجرام. يفحص استجابة `sendVideo`، ويحفظ الأرقام التي عُرضت للمراجعة، ويمنع `publish`.
- `clip_planner.py`: تحليل الأرقام العربية والإنجليزية، التحقق من التوقيتات والمدد، رفض رقم غير موجود، والتحقق من هوية خطة الاقتراحات حتى لا يعمل اختيار قديم على فيديو جديد.
- `telegram_poll.py`: مسار اختيار مماثل لمن يستخدم Telegram polling بدل Cloudflare webhook.
- `.github/workflows/main.yml`: تمرير `CLIP_IDS` و`CLIP_PLAN_REF` لتشغيل معاينة المقاطع المختارة.
- `worker.js`: **مهم جدًا**: تعديل Webhook على Cloudflare، وهو المسار الفعلي المستخدم في تيليجرام بحسب الرسائل المعروضة. يحتاج إلى نشر منفصل في Cloudflare؛ رفعه إلى GitHub وحده لا ينشره على Worker.
- `tests/test_stage2.py` و`tests/test_worker_stage2.mjs`: اختبارات محلية بلا شبكة، ولا نشر.

## خطوات التنفيذ — بالترتيب

1. احتفظ بنسخة احتياطية من مجلد المشروع وأكواد Cloudflare Worker الحالية.
2. فك ملفات التحديث في جذر مشروع `yt-auto-agent`، مع السماح باستبدال أسماء الملفات المتشابهة. **لا تستبدل أي ملف لم يظهر في هذا التحديث**.
3. شغّل `update_v5_fixed.bat` الموجود لديك، وراجع القائمة قبل الموافقة على الرفع. انتظر `SUCCESS`.
4. في لوحة Cloudflare افتح Worker المستخدم حاليًا للبوت (`majd-youtube-agent`)، ومن Edit Code استبدل كوده بمحتوى `worker.js` المرفق ثم اختر Deploy. **لا تغيّر** أسماء Secrets أو KV binding. المتغير السري `GITHUB_PAT` في Cloudflare يحتاج صلاحية قراءة/تعديل Actions Variables، وهو نفس نطاق الصلاحيات الذي نجح في حفظ الاقتراحات من GitHub Actions.
5. في تيليجرام أرسل **`/clip 1`** مباشرة إذا كانت قائمة الاقتراحات السابقة ما زالت محفوظة، أو **`/prepare`** لاستخراج اقتراحات جديدة أولًا. يمكن أيضًا إرسال `1` أو `١،٣` أو `/clip 1,3`.
6. انتظر رسالة بدء التنفيذ وفيديو معاينة لكل رقم. لا تستعمل `/publish`. راجع في GitHub Actions سجل `CLIP_PREVIEW: ... DELIVERED=YES` ثم `CLIP_SELECTION` / `اكتملت المعاينة`، وأرسل السجل إذا فشل.

## حدود المرحلة الثانية

- المقاطع الناتجة ستكون فيديوهات رأسية 1080×1920، كل منها مستقل، بدون نشر.
- **لا تتضمن كابشنز محروقة داخل الفيديو في هذه المرحلة**؛ إضافتها المتزامنة مرحلة ثالثة منفصلة بعد اعتماد نجاح القص والاختيار.
- `/seo` فقط عند الطلب، ولن ترسل `/clip` أو `/prepare` بيانات وصفية.
- `/publish` متوقف في Cloudflare Worker وفي `agent.py`. إرسال رقم لا يعني الموافقة على النشر.
- اختبارات محلية: 13 اختبار Python ناجح، و6 حالات Worker تجريبية ناجحة، واختبار عملي لـ FFmpeg على فيديو اصطناعي نجح. لم يجر تشغيل حقيقي على حسابك أو نشر كود Cloudflare من هذه البيئة.
- لا تشغّل webhook وpolling للبوت نفسه في الوقت ذاته.

**ملاحظة خصوصية:** لا ترفع `.env`، `cookies.txt`، رموز API أو ملفات جلسة. التحديث لا يتضمن أي أسرار.
