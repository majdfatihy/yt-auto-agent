# V5 — المرحلة الأولى: التحكم بالأوامر والمراجعة

هذه نسخة مبنية على لقطة V4 المتاحة في المحادثة، وليست سحبًا مباشرًا لآخر Commit من GitHub.

## الملفات المعدلة
- telegram_poll.py: حفظ المصدر؛ /menu و/status و/cancel و/seo و/prepare و/publish؛ عدم تشغيل شيء عند وصول رابط أو MP4.
- agent.py: فصل مهام SEO والمعاينة والنشر؛ منع نشر Facebook غير المطلوب؛ عدم إرسال مسودات Quora دون طلب.
- .github/workflows/main.yml: تمرير AGENT_ACTION؛ الافتراضي prepare.

## القيود الصريحة
- /publish ينشر على YouTube مباشرة بأمر صريح، لكنه يعيد معالجة المصدر ولا ينشر ملف المعاينة ذاته.
- لم تُنفذ أزرار Inline Keyboard ولا اختيار لقطات متعددة أو كابشنز متحركة أو جدولة أو قاعدة بيانات أو تكامل Pinterest/Instagram/TikTok/Quora/Medium.
- لا توجد معاينة حقيقية للقطات متعددة؛ يتم إرسال المقطع الواحد الناتج.
- إذا أُرسل MP4 بلا رابط ثم أُرسل الرابط كرسالة مستقلة غير رد، يُحفظ الرابط وحده؛ أرسل الرابط ردًا على الملف أو في تعليقه.
- المتغير TELEGRAM_LAST_SOURCE في GitHub Actions Variables يحفظ آخر مصدر واحد فقط، وليس قاعدة بيانات دائمة متعددة الفيديوهات.
- GitHub Actions schedule يعمل وفق الجدول السابق (كل خمس دقائق تقريبًا وليس وقتًا مضمونًا).
- يجب اختبار السلوك على المستودع الفعلي قبل اعتماد النشر.

## اختبارات موصى بها
1. أرسل رابطًا: تحقق من عدم تشغيل process_video.
2. /status يعرض الرابط.
3. /seo: يولد SEO دون قص أو نشر.
4. /prepare: يولد معاينة فقط دون رفع YouTube.
5. /publish: ينشر على YouTube بعد أمر صريح فقط.
6. /cancel ثم /status: لا يوجد مصدر.

## الأمان
- لا ترفع Secrets أو PAT إلى المستودع.
- نفّذ مقارنة Diff مع ملفات المستودع قبل الاستبدال؛ لا تستخدم force push.
