# المرحلة الأولى — اقتراح توقيتات القص فقط

## التعديلات المحددة

- `agent.py`: أمر `/prepare` لم يعد يشغّل المونتاج ولا يرسل بيانات SEO؛ يرسل اقتراحات مرقمة فقط. أمر `/publish` محجوب مؤقتًا حتى اكتمال الاختيار والموافقة.
- `clip_planner.py` (جديد): يبني حتى 5 اقتراحات من التوقيتات الحقيقية المستخرجة، ويتحقق من المدة وتداخل الكلام، مع بديل يعتمد على التفريغ عند تعطل Gemini. يحفظ قائمة الاقتراحات في GitHub Actions Variable باسم `TELEGRAM_CLIP_PROPOSALS`.
- `telegram_poll.py`: رسائل أوامر تيليجرام متوافقة مع المرحلة الأولى، ويُلغى حفظ الاقتراحات القديمة عند `/cancel` أو وصول مصدر جديد عبر هذا المسار.
- `.github/workflows/main.yml`: تمرير `GH_PAT` القائم بالفعل لتخزين الاختيارات في متغير GitHub.
- `.gitignore`: استبعاد ملفات الاعتماد والملفات المؤقتة الجديدة من الرفع باستخدام `git add -A`. لا يستبعد ملفات سبق تتبعها بـ Git.
- `tests/test_stage1.py`: 7 اختبارات محلية دون شبكة أو نشر.

## خطوات التشغيل

1. فك محتويات ملف التحديث مباشرة في جذر مشروع `yt-auto-agent` مع السماح باستبدال الملفات الأربعة التي تغيّرت (الملفات الأخرى إضافات).
2. شغّل ملف `update_v5_fixed.bat` الموجود عندك، وراجع قائمة الملفات المعروضة قبل تأكيد الرفع؛ تأكد أن `.env` والكوكيز ومفاتيح API غير متعقبة في Git.
3. في تيليجرام أرسل `/cancel`، ثم أرسل MP4 مرفقًا برابط يوتيوب في الـ caption، ثم `/prepare`.
4. انتظر وصول رسالة تبدأ بـ `اقتراحات القص — لم يتم قص أي فيديو` وتحتوي على مقاطع مرقمة بتوقيتات.
5. تأكد من إكمال `GitHub Actions` بنجاح، وفي `Settings → Secrets and variables → Actions → Variables` ينبغي ظهور `TELEGRAM_CLIP_PROPOSALS` (قد يتطلب PAT صلاحية Variables: write).

## ما لا تفعله المرحلة الأولى

- لا يوجد أمر اختيار `1` أو `/clip 1` حتى يتم تنفيذ المرحلة الثانية.
- لا يوجد قص أو توليد معاينة أو حرق كابشنز حتى المراحل التالية.
- `/seo` وحده يعرض البيانات الوصفية كما في النسخة السابقة.
- `/publish` متوقف عمدًا، حتى لا ينشر الوكيل مقطعًا قبل اختيارك وموافقتك.
- التحليل دون تفريغ صوتي مؤقت لا يقترح توقيتات غير موثوقة.

## شرط مهم

`GH_PAT` يجب أن يكون محفوظًا في Secrets مسبقًا، وله صلاحية قراءة وكتابة Actions Variables في المستودع. هو نفس السر المستخدم في سير `Telegram Inbox` الحالي. لا تضع قيمة المفتاح في الملفات أو المحادثة.

## نطاق الاختبار

تم فحص الصياغة البرمجية وتشغيل 7 اختبارات محلية مع طلبات API وهمية. لم يتم تنفيذ اختبار حقيقي ضد تيليجرام أو GitHub أو Gemini لأن مفاتيح الحساب لا تُستخدم خارج مشروعك.

هذه النسخة مبنية على ملف المشروع المرفوع في المحادثة، وليست مزامنة مباشرة مع GitHub.
